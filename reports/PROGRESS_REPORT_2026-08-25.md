# Android 앱 런타임 기능·보안 분석 자동화 중간 보고

- 기준일: 2026-08-25
- 분석 성격: 승인된 테스트 환경에서의 동적 정상 동작 관찰 및 보안 검토 우선순위화
- 현재 상태: 자동화 프로토타입 구현 및 1차 기능 탐색 완료
- 취약점 판정: 현재까지 확인된 취약점 없음

## 1. 요약

수작업으로 앱 기능을 하나씩 실행하고 로그를 해석하던 과정을 자동화했다. 시스템은
GLM-5.1이 저위험 UI 탐색 경로를 선택하고, 정책 엔진이 위험 행동을 차단하며,
Frida가 행동별 런타임 증거를 수집한다. 탐색이 끝나면 Codex가 정상 동작과 보안
검토 항목을 분석해 누적 기능 인벤토리로 통합한다.

가장 최근 검증 실행에서는 5개 UI 단계를 오류 없이 수행했고, 위험하거나 의미가
불명확한 후보 49개를 실행하지 않았다. 인증번호 입력 화면까지는 정상적으로
관찰했지만 값을 입력하거나 제출하지 않고 뒤로 이동했다.

현재 5개 기능을 분류했으며, 이 중 4개는 보안 검토 우선순위가 높고 1개는
중간이다. 이 등급은 민감 자산과 인증 경계에 대한 **검토 가치**를 뜻하며 취약점의
존재나 심각도를 의미하지 않는다.

## 2. 구현 범위

### UI 탐색과 실행 관리

- ADB/UIAutomator를 이용한 현재 화면과 interactive control 수집
- GLM-5.1을 이용한 다음 저위험 탐색 행동 선택
- 앱 시작·종료, Frida 세션, 행동 단위 로그 구간 관리
- 화면 안정화와 방문 화면 중복 방지

### 런타임 증거 수집

- 사용자 클릭과 입력 action correlation
- Activity와 Fragment 생명주기
- LiveData와 StateFlow 상태 변경
- HTTP 요청·응답과 목적지
- LOCO 요청·응답·Push ingress
- 실패와 지연시간
- raw payload 비수집 및 민감 헤더 값 축약

### 정책과 분석

- 기본 자동 실행 범위: `safe`
- 삭제, 차단, 메시지 전송, 통화, 결제 등 외부 효과 후보 차단
- 입력 fixture가 없는 임의 텍스트 입력 차단
- Codex를 이용한 행동별 정상 동작 분석
- 관찰 사실, 추론, 보안 미확인 사항 분리
- 기존 기능 ID 보존과 새 기능 자동 병합

## 3. 현재까지 분석된 기능

| 기능 ID | 기능 | 상태 | 검토 우선순위 | 현재까지 확인한 정상 동작 |
|---|---|---:|---:|---|
| `F_MORE_HUB` | 더보기 및 서비스 허브 | 관찰됨 | 높음 | MainActivity 내 더보기 탭으로 이동하며 설정, QR, Wallet, Pay, 자산, Mobile ID, Talk Cloud, Calendar 등의 진입점을 노출한다. 일부 설정·배지·날씨·결제 구성·콘텐츠 요청이 동반됐다. |
| `F_SETTINGS_HUB` | 일반 설정 허브 | 관찰됨 | 중간 | 더보기의 General Settings 선택 후 SettingActivity로 이동한다. 계정, 개인정보, 친구, 알림, 채팅, 백업, 데이터·저장공간 등의 하위 설정을 노출한다. |
| `F_PRIVACY_SECURITY_SETTINGS` | 개인정보·보안 설정 허브 | 관찰됨 | 높음 | SettingActivity의 Privacy 선택 후 PrivacySettingActivity로 이동한다. 개인정보, 기기 관리, 잠금 화면, 비밀번호 관리 등의 진입점을 노출한다. |
| `F_SUBDEVICE_MANAGEMENT` | 보조기기 관리 | 관찰됨 | 높음 | Manage Devices 선택 후 PCSettingsActivity로 이동하며 보조기기 설정 정보를 조회하고 인증번호 입력 진입점을 표시한다. |
| `F_SUBDEVICE_LOGIN_VERIFICATION` | 보조기기 로그인 인증번호 흐름 | 부분 관찰 | 높음 | 인증번호 입력 진입점 선택 후 LoginPassCodeActivity가 표시된다. 값 입력과 제출 없이 뒤로 이동해 PCSettingsActivity로 복귀했다. |

## 4. 관찰된 보안 관련 사항

- 더보기 및 설정 영역은 결제, 자산, 신원, 계정 보안 등 여러 민감 기능의 진입점을
  집약하므로 기능별 권한과 계정 상태 검증이 중요하다.
- 일부 HTTP 요청에서 인증 정보가 존재한다는 표시를 관찰했지만 실제 credential
  값은 분석 입력에 포함하지 않았고 서버 권한 검증 여부도 시험하지 않았다.
- 보조기기 관리와 인증번호 입력 흐름은 인증, 세션, 기기 바인딩 경계로 분류했다.
- 최신 5단계 구간에서 HTTP 요청 3개가 관찰됐으며 LOCO, WebSocket, Push 이벤트는
  관찰되지 않았다.
- 저장소 계측은 아직 포함되지 않아 credential, 인증 상태, 기기 목록 등의 로컬
  저장 여부와 보호 방식은 미확인이다.
- 성공적인 HTTP 200 응답이나 정상 화면 전환은 올바른 서버 권한 검증을 증명하지
  않는다.

## 5. 현재까지의 안전성 통제와 결과

- 정책 상한을 `safe`로 유지했다.
- 최신 실행에서 5개 행동을 수행하고 49개 후보를 차단했다.
- 메시지 전송, 통화, Pay 등 다른 사용자나 서비스에 영향을 줄 수 있는 행동은
  실행하지 않았다.
- 인증번호, 비밀번호, credential을 입력하거나 제출하지 않았다.
- 현재 결과는 취약점 증거가 아니라 후속 보안 검사를 위한 기능 지도와 우선순위다.

## 6. 미확인 항목

1. 각 설정과 보조기기 기능의 계정 상태·권한·entitlement 조건
2. 보조기기 목록 조회와 세션 폐기의 서버 측 권한 검증
3. 인증번호의 만료, 재사용, 시도 횟수 제한, 기기·세션 바인딩
4. 인증·기기 정보의 로컬 저장 위치와 암호화 또는 Keystore 사용 여부
5. 네트워크 단절, 만료 credential, 권한 거부, 잘못된 입력 시 실패 처리
6. 동일 화면에서 발생한 background 요청과 사용자 행동 유발 요청의 인과관계
7. Java/OkHttp/LOCO hook 외 native transport의 존재 여부

## 7. 다음 단계 제안

### 우선순위 1: 인증·기기 관리 표적 분석

- 승인된 테스트 계정 2개 이상으로 권한과 계정 상태 차이를 비교한다.
- 보조기기 조회, 등록, 해제, 인증번호 흐름을 각각 독립 실행으로 수집한다.
- 만료·오입력·재사용·과도한 시도 등 통제된 실패 시나리오를 별도 승인 후 확인한다.

### 우선순위 2: 저장소와 credential lifecycle

- SharedPreferences, DataStore, SQLite, 파일, Android Keystore 접근을 계측한다.
- 로그인·로그아웃·기기 해제 전후에 세션 및 인증 상태가 어떻게 정리되는지 확인한다.

### 우선순위 3: 기능 범위 확대

- 개인정보, 잠금 화면, 비밀번호 관리 기능을 한 run당 한 기능으로 분리해 탐색한다.
- Wallet, Pay, Mobile ID 등은 별도의 승인 범위와 테스트 계정 조건을 정한 후 진행한다.
- Push나 background 동작은 일반 UI crawl과 분리한 시나리오로 수집한다.

## 8. 재현과 산출물

```text
사용자 행동
  → UI 전환
  → 앱 내부 상태 변경
  → HTTP/LOCO/Push 관찰
  → 응답·UI 반영
  → Codex 정상 동작 분석
  → 기능 인벤토리 병합
```

공개 저장소에는 자동화 코드, Frida 계측 스크립트, 정책, 스키마, 테스트와 이
비식별화 보고서만 포함한다. APK, 디컴파일 결과, 원본 로그, 스크린샷, API 키,
사용자·기기·세션 식별자는 포함하지 않는다.

## 9. 결론

프로토타입은 정상 동작한다. 사람이 모든 화면을 수작업으로 누르지 않아도 저위험
탐색, 행동별 증거 수집, Codex 분석, 기능 인벤토리 누적까지 하나의 흐름으로 수행할
수 있다. 현 단계의 주요 성과는 취약점 발견 자체보다 **반복 가능한 기능 지도와
보안 검사 우선순위 생성 체계**를 확보했다는 점이다.
